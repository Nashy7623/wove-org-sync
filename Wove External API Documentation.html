Wove External API Documentation

The Wove External API allows you to programmatically access document processing, shipment management, and validation capabilities.

Features

  • OAuth 2.0 Authentication: Secure client credentials flow
  • Rate Limiting: Configurable per-client rate limits
  • Document Processing: Upload, validate, and merge shipping documents
  • Shipment Management: Create and manage shipment records with validation and merge operations
  • Webhooks: Get notified of document processing events (extraction, validation, merge)
  • Comprehensive Error Handling: Detailed error responses with troubleshooting information

Getting Started

  1. Create OAuth Client: Contact your account manager to create OAuth credentials
  2. Get Access Token: Use client credentials flow to obtain bearer token
  3. Make API Calls: Include bearer token in Authorization header
  4. Handle Rate Limits: Monitor rate limit headers in responses

Authentication

All API endpoints require OAuth 2.0 authentication using the client credentials flow.

Getting an Access Token

curl -X POST https://api.wove.com/api/v1/external/auth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "client_credentials",
    "client_id": "your_client_id",
    "client_secret": "your_client_secret"
  }'

Using the Access Token

Include the access token in the Authorization header:

curl -H "Authorization: Bearer your_access_token" \
  https://api.wove.com/api/v1/external/shipments

Rate Limiting

All endpoints are subject to rate limiting based on your OAuth client configuration:

  • Per-minute limit: Default 60 requests/minute
  • Daily limit: Default 10,000 requests/day

Rate limit information is included in response headers:

  • X-RateLimit-Limit-Minute: Your per-minute limit
  • X-RateLimit-Remaining-Minute: Remaining requests this minute
  • X-RateLimit-Reset-Minute: When the minute window resets
  • X-RateLimit-Limit-Day: Your daily limit
  • X-RateLimit-Remaining-Day: Remaining requests today
  • X-RateLimit-Reset-Day: When the daily window resets

Webhook Security

All webhook payloads are signed using HMAC-SHA256 for verification:

// Verify webhook signature
const crypto = require('crypto');
const signature = request.headers['x-wove-signature'];
const payload = JSON.stringify(request.body);
const expectedSignature = crypto
  .createHmac('sha256', your_webhook_secret)
  .update(payload)
  .digest('hex');

const isValid = crypto.timingSafeEqual(
  Buffer.from(signature),
  Buffer.from(expectedSignature)
);

Headers included with every webhook:

  • X-Wove-Signature: HMAC-SHA256 signature of the payload
  • X-Wove-Event: Event type (e.g., "extraction.completed")
  • X-Wove-Timestamp: ISO timestamp when the webhook was sent

Error Handling

All errors follow a consistent format:

{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "One or more documents not found or access denied",
    "details": {
      "field": "documentIds",
      "value": ["invalid_id"]
    }
  }
}

Error Codes

  • VALIDATION_ERROR - Invalid request parameters or data validation failure
  • AUTHENTICATION_ERROR - Invalid or expired credentials
  • AUTHORIZATION_ERROR - Insufficient permissions for the requested operation
  • NOT_FOUND - Requested resource not found
  • RATE_LIMIT_ERROR - Too many requests, rate limit exceeded
  • INTERNAL_ERROR - Internal server error

See the common error responses in the components section for detailed examples.
